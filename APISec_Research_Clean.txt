```
The page introduces **apisec Surface**, a free, open-source toolset designed to
help organizations discover, inventory, and secure the expanding "attack
surface" of modern applications—especially those incorporating AI, APIs, and
agents.
```

```
Its core mission is to **find every entry point** (from code to live traffic)
before attackers do, without sending data outside your environment. It focuses
on **AI-specific risks** (like LLM SDKs, agent frameworks, and MCP servers)
alongside traditional API and application endpoints.
```

# `### Key Capabilities` 

```
*   **AI Surface**: A static code analyzer that scans source code for AI
components across 12+ providers and frameworks (LangChain, CrewAI, etc.). It
flags 13 risk indicators and runs 100% locally as a GitHub Action.
```

```
*   **APIsec Bolt (Code)**: A GitHub Action that detects API frameworks (Spring
Boot, FastAPI, etc.) and generates OpenAPI 3.0 specs from code to catch
undocumented "shadow" endpoints in CI.
```

```
*   **APIsec Bolt (Browser Extension)**: Captures live API traffic directly from
your browser, filtering noise to build a real-time inventory of endpoints
without proxies.
```

```
*   **MCP Audit**: Scans Model Context Protocol configurations for secrets,
shadow APIs, and misconfigurations, generating AI-BOMs for compliance.
```

```
*   **App Surface**: Maps routes and parameters from source code to identify
undocumented endpoints before they reach production.
```

```
*   **Agent Audit**: Checks AI agents for authorization gaps and over-
permissioned tool calls.
```

# `### Outputs & Integration` 

```
Instead of just listing endpoints, the tools generate three types of Bill of
Materials (BOMs):
```

`1.  **AI-BOM**: Inventory of AI components and risks.` 

`2.  **API-BOM**: List of all API endpoints.` 

`3.  **S-BOM**: Software Bill of Materials.` 

```
These can be gated in your CI/CD pipeline at the **Pull Request (PR)** stage,
ensuring high-risk findings are caught as a "diff" rather than in production.
```

# `### Philosophy` 

```
The page emphasizes a two-part approach:
```

`1.  **Mapping**: apisec Surface provides a free, static map of your entire attack surface at PR time.` 

`2.  **Proof**: apisec (the commercial platform) proves which of those mapped endpoints are actually *exploitable* at runtime.` 

```
The tools are designed to be **private by design**—nothing leaves your machine—
and to give CISOs a one-page summary to justify security investments.
```

calls, sends no telemetry, and requires no credentials, so your source never
leaves the host.

First run on a mature repo
The first run maps the AI surfaces already present in the codebase. The pattern
that scales is to baseline existing surfaces, then gate only new high-risk
findings in pull requests:
ai-surface scan . --update-baseline           # 1. snapshot today's inventory
ai-surface scan . --baseline                  # 2. show only what changed
ai-surface scan . --baseline --fail-on high   # 3. in CI, fail only on NEW high+
risk
--baseline --fail-on high is the recommended PR gate: low-noise, non-blocking on
pre-existing debt, and actionable.
```

```
GitHub Action and CI gating
The fastest path is one command from your repo root:
ai-surface init
It writes the recommended workflow below into .github/workflows/ai-surface.yml
and prints a pre-commit snippet for local scans (the repo ships .pre-commit-
hooks.yaml).
```

```
Or drop this into .github/workflows/ai-surface.yml yourself:
```

```
name: AI Surface Check
on: [pull_request]
permissions:
  contents: read
  pull-requests: write   # required when comment-on-pr is true
jobs:
  ai-surface:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # required for base-vs-head diff
      - uses: apisec-inc/AI-Surface@v1
        with:
          path: '.'
          comment-on-pr: 'true'
          fail-on: 'high'  # fail only on NEW high-or-critical findings
Every PR gets a sticky comment showing what changed in the PR, not just the
current repo state. fail-on gates on assessed severity, so inventory-only
findings do not fail the build. With fail-on: high, the build fails only when
the PR introduces a new high-or-critical finding.
```

```
No API keys are required. The action uses the built-in GITHUB_TOKEN to post or
update the PR comment.
```

```
For non-GitHub CI, the gate is just an exit code:
```

# `ai-surface scan . --fail-on high`

# `How it works` 

```
ai-surface maps AI surfaces from source code and configuration. It reads files,
matches known AI-surface signatures, runs deep-dive audits where enough evidence
exists, attaches governance mappings, and produces reports for developers, CI
systems, and security teams.
```

```
The CLI executes no code, uses no credentials, sends no telemetry, and makes no
network calls.
```

```
When PR comments are enabled, the GitHub Action uses the repository's
GITHUB_TOKEN to post or update a comment through the GitHub API. It does not
send source code, findings, or metadata to APIsec.
```

```
Deep dive: docs/ARCHITECTURE.md.
```

```
Comparison with adjacent tools
Trivy checks container images, Gitleaks checks git history, an SCA checks
dependencies. ai-surface is the equivalent pre-merge check for the AI layer. It
sits alongside the tools below rather than replacing any of them.
```

```
ToolWhat it tells youWhen it sees AI
SAST (Semgrep, CodeQL)Code-pattern vulnerabilitiesAfter commit; usually does
not build an AI surface inventory
DAST (Burp, ZAP)Reachable web vulnerabilitiesAfter deploy; sees HTTP behavior,
not LLM/agent internals
SCA (Snyk, Dependabot)Vulnerable dependenciesAfter commit; sees packages, not
how AI components are used
Observability (Helicone, LangSmith, Arize, Phoenix)What LLM calls happened at

ai-surface does not replace these tools. It focuses on the local, PR-time AI
attack-surface gap that most adjacent tools do not cover directly.
```

# `What it does not do` 

```
Runtime telemetry or behavior monitoring. Use tools like Helicone, LangSmith,
Arize, or Phoenix.
```

```
Runtime exploit validation. ai-surface maps and audits statically; it does not
prove exploitability against a running app (see Runtime validation).
Prompt injection, jailbreak, bias, or accuracy testing. Out of scope by design.
ai-surface is a structural analyzer, not a model evaluator.
Full cross-file dataflow for tool resolution. Regex/AST-light today; agent tools
```

```
built through factory functions may not be fully resolved. Treat the map as a
strong floor, not proof of complete coverage. AST/dataflow is the top roadmap
item.
```

```
Secret-value reads or PII classification. Secrets are reported by name and type
only, with values redacted. Use a dedicated secret scanner for value-level
coverage.
