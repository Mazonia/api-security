🧪 Comprehensive Testing Guide

How to Test MazAPI Features on External Websites, AI Agents & IoT Devices

Detailed step-by-step testing workflows with copyable commands, target examples, and expected visual results.

🌐
Browser Extension

1. Test Chrome Side Panel on Any External Website

🎯 Target Example: http://localhost:8000/ui or https://jwt.io or your own web app

Intercept live traffic, harvest Bearer tokens, decode JWT claims for alg:none bypasses, and replay tampered BOLA/IDOR requests directly in your browser.

Step 1
Open Chrome or Brave and load the unpacked extension from ./mazapi-extension in chrome://extensions.
Step 2
Navigate to your website (e.g., http://localhost:8000/ui) and press Ctrl+Shift+Y (or click extension icon) to open the BOLT Side Panel.
Step 3
Log in as user alice (pass: alice123). Notice the panel automatically captures Bearer tokens and decodes JWT payload claims inline.
Step 4
In the captured endpoint list, click GET /users/1. Change the parameter ID from 1 to 2 using Smart Parameter Picker.
Step 5
Click Replay Request. Watch user bob's private profile exfiltrated directly in the panel.
✅ Expected Output: Panel alerts "Weak Secret (secret)", "Missing Exp Claim", and shows Bob's data on parameter tampering (BOLA Vulnerability Verified).
Extension Folder: ./mazapi-extension (Manifest V3) | Shortcut: Ctrl+Shift+Y

AI Agent Audit

2. Audit Your AI Agents & Generate CycloneDX AI-BOM

🎯 Target Example: LangChain, CrewAI, AutoGen, Swarm, Bedrock Agent Python files

Audit autonomous AI agent graphs for authorization gaps, unconstrained shell execution, confused deputy risks, and cyber-physical actuation violations.

Step 1
Open terminal in your project workspace directory.
Step 2
Run AI Agent auditor with regulatory governance flags (EU AI Act Art. 14/15, NIST AI RMF, ISO 42001):
python api-security-project/cli.py agent-audit scan ./api-security-project/agent_audit --governance
Step 3
Export a structured CycloneDX 1.6 Artificial Intelligence Bill of Materials (AI-BOM) for your model pipeline:
python api-security-project/cli.py agent-audit scan ./api-security-project/agent_audit --format ai-bom -o ./ai-bom.json
✅ Expected Output: Flags 'unlock_door' tool executing without Human-in-the-Loop approval & generates compliant ai-bom.json detailing models & tool sinks.

IoT & Edge Security

3. Audit Embedded IoT Devices, Microcontrollers & OTA

🎯 Target Example: ESP32 / Arduino C/C++ firmware (.ino, .cpp), MQTT brokers, CoAP servers

Parse C/C++ AST syntax trees for microcontroller routes, audit MQTT broker wildcard ACLs, CoAP reflection, and unsigned OTA firmware updates.

Step 1
Scan embedded C/C++ microcontroller source files (ESP-IDF httpd_register_uri_handler, Arduino WebServer):
python api-security-project/cli.py app-surface scan ./api-security-project/vulnerable-api --format table
Step 2
Run dynamic IoT vulnerability probes against your live target device or local API container:
python api-security-project/cli.py iot-audit --target http://localhost:8000
✅ Expected Output: Uncovers IOT-OTA-01 (Unauthenticated & Unsigned Firmware Upload) and IOT-ACT-01 (Unauthenticated Door Lock Actuation).
🎯
Active DAST Scanner

4. Run Active DAST Scans Against Your Live REST APIs

Execute zero-egress dynamic security probes testing OWASP API Top 10 (SQLi, BOLA, BFLA, CORS, Rate Limiting, SSRF) against any URL.

Step 1
Target your local, staging, or production REST API with Bearer JWT token authentication:
python api-security-project/cli.py scan --target http://localhost:8000 --auth "Bearer YOUR_JWT_TOKEN"
Step 2
Export scan results as GitHub SARIF 2.1.0 format for automated CI/CD PR checks:
python api-security-project/cli.py scan --target http://localhost:8000 --format sarif -o ./scan-results.sarif
✅ Expected Output: Generates detailed scorecard detailing vulnerable endpoints, actual payloads, severity ratings, and remediation steps.
⚡
AST Surface Engine

5. Scan Source Code AST & Git PR Shadow Route Diffs

🎯 Target Example: Python, Node.js, Java, .NET, Go, PHP, C/C++ git repos

Extract API endpoints straight from source code syntax trees before building Docker images or deploying code to production.

Step 1
Run multi-language AST surface discovery on your project directory:
python api-security-project/cli.py app-surface scan ./api-security-project/vulnerable-api --format table
Step 2
Compare two Git branches (or PR Base vs Head) to catch undocumented shadow APIs:
python api-security-project/cli.py app-surface diff --base main --head feature-branch /path/to/repo
✅ Expected Output: Displays grade (e.g. Grade F 50/100), 45 mapped endpoints, missing auth flags, and newly introduced shadow routes.
